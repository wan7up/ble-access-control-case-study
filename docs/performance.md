# 性能与取舍

## 主要耗时来源

一次自动开门的时间通常由以下部分组成：

1. 浏览器启动 BLE 广播监听。
2. 等待足够的广播样本。
3. 查询浏览器已授权设备。
4. 建立 GATT 连接和发现服务。
5. 发送服务端请求并等待响应。
6. 等待门禁通知挑战。
7. 写入响应并等待门禁回执。

其中第 2、4、6、7 步受现场无线环境和门禁设备状态影响，页面只能设置合理上限，不能保证固定耗时。

## 已采用的优化

- HTTP 与 GATT 连接在设备确定后并行启动。
- 已授权设备优先使用浏览器的持久授权，减少重复选择。
- 非空门禁列表做缓存，并提供手动重新授权入口。
- 单个候选达到最低样本条件后可提前结束扫描。
- 多设备时用平均 RSSI 排序。
- 对服务端开门接口设置限流，避免重复点击造成重复请求。

## 不宜盲目缩短的部分

- 把扫描窗口缩得过短，可能漏掉广播较慢或信号较弱的门。
- 只取一个 RSSI，容易在相邻门之间误判。
- 先固定尝试高频门，可能在另一扇相邻门前误开。
- 去掉第二次尝试的间隔，可能触发服务端限流。
- 自动重试真实开门请求，会让失败原因和实际状态更难判断。

## 建议的测量方式

每次测试只比较一个版本，至少记录 5 次：

```text
点击时间
扫描监听就绪时间
首次发现目标时间
扫描完成时间
GATT 连接时间
HTTP 响应时间
门禁回执时间
现场实际结果
```
