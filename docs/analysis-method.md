# 分析方法

## 1. 抓包

在自有测试账号和获授权设备上：

1. 在 Mac 上启动 mitmproxy/mitmweb。
2. 让 iPhone 与 Mac 处于可通信网络。
3. 在 iPhone 上配置 HTTP 代理。
4. 仅在测试设备上安装并信任 mitmproxy CA 证书。
5. 先用普通网页确认代理生效，再操作测试 App。
6. 对每次点击记录时间、界面动作、HTTP 请求、响应和 BLE 现象。

应优先比较多次相同动作，而不是依据一次请求下结论。特别要区分：

- 登录、刷新授权、获取门列表。
- 点击开门时的服务端请求。
- BLE 扫描、连接、服务发现、通知和写入。
- 成功、距离不足、设备未授权和网络失败。

## 2. APK 静态分析

在有权分析的 APK 上，搜索以下类别的线索：

- HTTP 客户端和接口路径。
- 请求签名、会话和设备 ID。
- BluetoothGatt、BluetoothLeScanner、特征值读写。
- 服务 UUID、通知回调和错误处理。
- 日志中的阶段名称。

静态分析的目标是理解流程，不是提取可用于真实门禁的密钥或复制第三方认证机制。

## 3. 动态验证

把动作拆成独立阶段，每次只改变一个变量：

```text
同一账号 + 不同门
同一门 + 不同距离
同一门 + 有/无 Bluefy 授权
同一门 + 网络可用/不可用
同一门 + 只发 HTTP / 完整 BLE 流程
```

所有测试都应在测试者有权使用的设备上进行，并在记录中隐藏原始身份信息。
